# 架构说明

## 数据流总览

```text
群聊 / 私聊
    |
    +--> 消息库(SQLite) --(增量读取)--> mindscape_diary --LLM提炼--> memory.md / people.md
    |                                        |                     |
    |                                        +--(按天压缩)--> digest.md
    |                                                              |
    |                            (分层注入: 规矩 / 账本 / 摘要 / 原文)
    |                                                              v
    |                                                    system prompt
    |                                                              ^
    |   notes.md <--(bot 当场写: save_note 工具)--------------------+
    +--> 图片消息 --(概率采样)--> mindscape_stickers --视觉判定--> 分类图库
                                                                  |
                                                          (选图/强制配图)
                                                                  |
   memory.md / digest.md / notes.md <--(按需检索: recall_memory)----+
                                                                  v
                                                        回复链 -> guard 拦截 -> 发送

  [运维] mindscape_janitor: 定期清理会话，防止请求膨胀导致超时
```

## 为什么这样分层

| 层 | 解决的问题 | 关键取舍 |
|---|---|---|
| **唤醒** | 该说时不说 / 不该说时乱说 | 判定在框架的 `waking_check` 阶段（比插件更早），以补丁形式提供 |
| **认知** | 记忆丢失 / prompt 膨胀 | 记忆存 **Markdown 文件**（人类可读），注入只取**最近 N 字** |
| **表达** | bot 不会用图 | **低概率采样**（省 API）+ **分类隔离**（不串味） |
| **沉浸** | 报错外泄 | **发送前拦截**（最靠后的钩子，兜得住） |
| **运维** | 历史膨胀导致超时 | **定期清理**，与记忆解耦 |

## 关键设计决策

### 1. 记忆为什么不用数据库？

因为**人类可读**。你可以直接打开日记文件看 bot 记住了什么，
出问题时一眼就能看出来，不需要写查询语句。

### 2. 为什么注入只取「最近 N 字」？

因为**成本恒定**。无论记忆文件涨到 1KB 还是 1MB，
每轮请求的 token 消耗都一样。更早的记忆交给 `recall` 工具按需检索。

### 3. 为什么要「概率强制配图」？

因为 chat bot 有极强的**只发文字惯性** —— 光给它工具，它不用。
必须由框架层面推一把。

### 4. 为什么报错拦截放在最后？

因为那是最靠后的钩子（发送前），**兜得住所有上游异常**。

### 5. 为什么人物画像要分成「权威关系」和「自动整理」两段？

因为**摘要模型不知道谁是谁**。它的输入只有聊天记录，能看出的最多是
「这个人常发图」，于是会把作者写死的「喜欢的人」降级成「群友」——
bot 于是认错人。关系是**作者写的**，不该交给摘要模型去猜。

`relations` 从人格档案里取「关系与称呼」那一段，放在画像开头，
自动整理永不覆盖它，**历史上已经被降级的条目也会被清掉**
（只挡新的不够 —— 旧的那条会一直躺在文件里继续误导 bot）。

放在最前面还有一个副作用：`read_people` 是按从头截断的，
权威关系因此**永远切不掉** —— 排序靠后的普通群友可以被截，
重要的人不会。

### 6. 为什么「空回复救援」不能挂在 `on_decorating_result`？

因为**空回复没有 chain**。`result_decorate/stage.py` 开头就是

```python
if result is None or not result.chain:
    return
```

结果没成形，装饰阶段根本走不到钩子 —— 挂在「结果成形之后」去救
「结果没能成形」，是自相矛盾的。要救这种情况必须挂更早的
`on_llm_response`（由 agent 的终止步派发，此时 `final_llm_resp`
就是同一个对象，改写 `completion_text` 会被直接采用）。

## 模块清单

| 模块 | 层 | 职责 | 依赖 |
|---|---|---|---|
| `mindscape_core` | 共享 | 纯函数：索引读写、路径校验、判定类型校验、跨进程锁 | 无框架依赖 |
| `mindscape_config` | 共享 | 配置读取（YAML，带缓存与失败降级） | 无框架依赖 |
| `mindscape_guard` | 沉浸 | 报错拦截 + 日志脱敏 | core |
| `mindscape_memory` | 认知 | **分层注入**（规矩 / 账本 / 摘要 / 原文）+ 人物画像 | core / config |
| `mindscape_recall` | 认知 | 按需检索（混合检索 + 多词 + 边界自知 + 转述≠事实） | core / config |
| `mindscape_diary` | 认知 | 增量读消息库 → LLM 提炼 → 写 Markdown | core / config（独立脚本） |
| `mindscape_digest` | 认知 | 把「已过完的一天」压成摘要（分层记忆的骨架层） | core / config（独立脚本） |
| `mindscape_notes` | 认知 | **bot 当场可写的账本**（save_note 工具，原子写） | core / config |
| `mindscape_stickers` | 表达 | 概率采样图片 → 视觉判定 → 分类入库 | core / config |
| `mindscape_sticker_use` | 表达 | 选图发送 / 概率强制配图 / 斗图队形 / 存图工具 | core / config |
| `mindscape_rescue` | 沉浸 | 空回复救援（推理模型只吐 reasoning 时补一次轻量调用） | core / config |
| `mindscape_format` | 沉浸 | 把多段回复压平 | config |
| `mindscape_janitor` | 运维 | 会话防膨胀清理 | core / config（独立脚本） |

> 标「共享」的两层是纯逻辑，**可以脱离 bot 框架单独运行与测试**。

## 数据格式

### 素材索引（JSON）

```json
[
  {
    "file": "a1b2c3d4e5.jpg",
    "category": "bot-name",
    "name": "无语猫猫",
    "tags": ["无语", "嫌弃", "敷衍"],
    "desc": "适合表达懒得搭理的场景。"
  }
]
```

- `file` 是**内容哈希前 10 位**，天然去重
- `category` 用于**多 bot 隔离**：每个 bot 只挑自己分类的图
- 索引整体**原子替换**写入，读写都在**跨进程锁**内，避免与采集任务互相覆盖

### 长期记忆（Markdown）

```markdown
## 2026-01-01 20:30
- 群友 A 说了件有趣的事。
- 群友 B 和 C 在争论什么。

## 2026-01-02 09:15
- ……
```

为什么用 Markdown 而不是数据库：**人类可读**。出问题时直接打开看，
不用写查询语句；用户也可以手工修订。注入时只取文件**末尾 N 字**，
按条目边界裁剪，长度是硬上限。

## 三条核心链路

### 链路一：长期记忆（认知）

```text
① 定时任务：mindscape_diary 增量读消息库
      | 按「时间 + 序号」游标，只处理新消息
      | 交给 LLM 提炼成「事件 / 人物」
      | 任一失败则中断，游标只推进已成功的部分（不丢消息）
   -> 追加写入 memory.md 与 people.md

② 每轮对话：mindscape_memory 挂在 on_llm_request
      | 按四层拼装，每层独立字数预算（硬上限，按条目边界裁剪）：
      |   规矩（rules）→ 账本（notes.md）→ 摘要（digest.md）→ 原文（memory.md）
      | 拼进 system_prompt
   -> 模型带着「记忆」生成回复

③ bot 自己记一笔：聊到需要记住的细节
      | 模型调用 save_note(key, value)
      | 同名就地覆盖并挪到末尾（最新的优先被注入）
   -> 同一件细节不会每次答得不一样

④ 用户问「几天前的事」
      | 模型自主调用 recall_memory(keyword)
      | 混合检索：完整子串命中 100 分；
      |           否则去掉虚词后按命中率给分，命中率 < 60% 直接判为不相关
      | 结果里报**真实命中总数**，并提示「命中条数 ≠ 个数」「转述 ≠ 事实」
      | 返回带时间戳的原文，并附「只依据这些回答，没有就说想不起来」
```

### 链路二：素材表达

```text
采集：任何消息（群 / 私信）
      | 以 sample_prob 采样
      | 取图片 -> MD5 去重（键为 category:hash）
      | 视觉模型判定「是否契合人设」
      | 判定失败不记为已见（允许重试）；明确不相关才记
   -> 入库 + 写索引（加锁 + 原子替换）

使用（两条路）：
  a) 模型主动：调用 send_sticker(want)
  b) 框架强制：回复发送前按 force_prob 掷骰子
      | 斗图队形：若 90 秒内同一张图出现 >= 2 次，则提高跟进概率
      | 给 LLM 候选列表（只含本 bot 的分类）
      | 模型选最贴语气的一张 -> 追加到回复链
```

### 链路三：沉浸保护

```text
模型全部失败 -> 框架生成错误文本，准备当回复发出
      | on_decorating_result(priority=999) 拦截
      | 命中特征（内置规则 + 用户追加规则）
      | 清空整条回复 + 停止事件
   -> 用户侧表现为「这次没说话」，而不是「吐了一句报错」

同时：日志只记录脱敏摘要（抹掉疑似密钥 / 带令牌的 URL）
```

## 部署形态

源码是**模块化**的（便于维护），但部署时会被合并成**单文件单类**：

```text
plugins/mindscape_*.py   --(scripts/build_plugin.py)-->   dist/mindscape/main.py
  模块化源码，各自独立                                    单文件 + 单插件类
```

**为什么必须合并**（两条实测确认的框架约束）：

1. 插件之间**不能互相 import** —— 框架把每个插件当独立包加载；
2. 框架**只实例化一个插件类**（名字以 plugin 结尾或叫 Main）。

所以构建器用 `ast` 把各模块拆成「导入 / 类 / 其他」，
再把各类合成一个 `MindscapePlugin`；
各模块的配置属性使用**互不重叠的前缀**（`s_c` / `u_c` / `f_c` …），
避免合并后互相覆盖。

## 扩展指南

### 加一个新能力模块

1. 在 `plugins/` 新建 `mindscape_xxx.py`
2. 需要钩子就写成 Mixin 类（`class XxxMixin:` + `def setup(self, context)`）；
   需要给模型用就写模块级 `@llm_tool` 函数（见下）
3. 把名字加进 `scripts/build_plugin.py` 的 `ORDER` 与 `MIXIN_ORDER`
4. 重新构建，并在 `scripts/run_selfcheck.py` 里补一条断言

### 写模块级工具的坑

框架用 `functools.partial(handler, 插件实例)` 绑定，
所以模块级函数的**第一个位置参数收到的是插件实例**，不是 event：

```python
@llm_tool(name="my_tool")
async def my_tool(*args, **kwargs):
    ev = None
    for a in args:
        if hasattr(a, "get_self_id"):
            ev = a
            break
```

### 适配其他 bot 框架

本项目与框架的接触面只有三处：

| 接触点 | 需要什么 |
|---|---|
| 消息钩子 | 「收到消息」「请求前」「发送前」三个时机 |
| 图片对象 | 能把消息里的图片落到本地路径 |
| 工具注册 | 能把函数暴露给模型调用 |

其余（配置、检索、判定、索引、清理）都是**纯 Python**，可直接复用。
